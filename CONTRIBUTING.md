# Как участвовать в проекте

[English](CONTRIBUTING.en.md)

## Что считается официальным

Сборки и релизы, выложенные автором на странице продукта и в разделе
Releases, — официальные. Всё остальное — форки, перепакованные сборки,
патчи, наложенные поверх, — неофициальное, даже если работает.

Правка становится официальной не сама по себе, а тогда, когда автор её
принял: посмотрел, влил и указал авторство изменения. В официальном релизе
имя автора правки стоит рядом с именем автора проекта — на первом экране
приложения и в истории изменений.

Это не закрытость и не запрет: правки принимаются, и авторство сохраняется.
Просто «официальным» делает правку решение автора, а не её наличие.

## Подпись коммитов (DCO)

Каждый коммит должен содержать строку `Signed-off-by` — это Developer
Certificate of Origin. Достаёт её одна опция:

```bash
git commit -s -m "Понятное сообщение"
```

`-s` добавляет строку вида:

```
Signed-off-by: Имя <почта>
```

Это подтверждение: «я написал этот код (или он из подписанного источника),
я имею право отдать его под лицензией проекта, и делаю это добровольно».

Подпись нужна, чтобы автор мог позже перелицензировать проект целиком, не
договариваясь с каждым отдельно.

## Как прислать правку

1. Сделайте ветку от `main`.
2. Внесите изменения, каждый коммит — с `-s`.
3. Откройте pull request в `main`.
4. Опишите, что изменилось и зачем.

Проверка `Build and validate workflows` должна пройти: она собирает проект и
проверяет workflow-файлы. Проверка подписи требует, чтобы у каждого коммита
в pull request была строка `Signed-off-by`.

## Что приветствуется

- Исправления и мелкие улучшения, с описанием «что было не так и что стало».
- Переводы: в приложении два языка, и переводы иногда отстают.
- Сообщения об ошибках с шагами воспроизведения.

## Что не приветствуется

- Правки, меняющие лицензию или условия использования.
- Тяжёлые зависимости ради одной мелкой функции.
- Правки, которые ломают офлайн-режим: приложение не должно начать ходить
  в сеть.
- Перепакованные сборки, выложенные как свои, — это неофициальные сборки, и
  о них стоит сказать автору, а не выкладывать от имени проекта.
